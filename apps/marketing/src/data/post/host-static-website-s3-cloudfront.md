Amazon S3 behind CloudFront is one of the most reliable ways to host a static website — an Astro, Hugo, Next.js export or plain HTML site. Here is why it is still a solid choice:

1. **Availability**: S3 is designed for 99.99% availability and CloudFront serves your pages from hundreds of edge locations.
2. **Scalability**: a traffic spike needs zero configuration — there is no server to size.
3. **Security**: the bucket stays private; only your CloudFront distribution can read it.
4. **Performance**: HTTP/2, HTTP/3 and edge caching worldwide.
5. **Cost**: for a small or medium site you typically pay cents per month — often just the $0.50 Route 53 hosted zone.

**Setup in about 15 minutes. Deploys in 10 seconds.** I used exactly this setup for [maltaexpat.com](https://maltaexpat.com).

## Architecture

- **S3** stores the files. The bucket is **private** — no public access, no "static website hosting" feature.
- **CloudFront** serves the site over HTTPS and reads the bucket through **Origin Access Control (OAC)**.
- **AWS Certificate Manager (ACM)** provides the free TLS certificate.
- **Route 53** points your domain to the CloudFront distribution.

> Older tutorials (including earlier versions of this one) start with a public bucket and the S3 website endpoint, or use Origin Access Identity (OAI). AWS now recommends a private bucket with OAC: OAI is legacy, and new buckets block public access by default anyway. This guide goes straight to the recommended setup.

## Prerequisites

- An AWS account
- A static site that builds to a folder (`dist/`, `public/`, `out/`…)
- The [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html) installed and configured
- A domain name (registered in Route 53 or elsewhere — you just need to manage its DNS in Route 53)

## 1. Create a private S3 bucket

In the S3 console, click **Create bucket**, pick a globally unique name and a region, and **keep "Block all public access" enabled** (the default). Object Ownership stays on "ACLs disabled" and default encryption (SSE-S3) is already on.

Or from the command line:

```bash
aws s3 mb s3://my-static-website-bucket --region eu-west-3
```

That's it: no bucket policy yet, no website hosting to enable. The policy will be generated by CloudFront in step 3.

## 2. Request a free HTTPS certificate (ACM)

CloudFront only uses certificates from the **`us-east-1`** region, whatever region your bucket is in.

- Open **AWS Certificate Manager** in `us-east-1` and click **Request a public certificate**
- Add your domain with and without `www` (`example.com` and `www.example.com`)
- Choose **DNS validation**
- Once created, open the certificate and click **Create records in Route 53**

The certificate is issued within a few minutes. **Keep the validation CNAME records**: ACM uses them to renew the certificate automatically every year. Deleting them means the certificate silently fails to renew.

## 3. Create the CloudFront distribution with OAC

In the CloudFront console, click **Create distribution**:

- **Origin domain**: select your bucket from the list. It must be the S3 REST endpoint (`my-static-website-bucket.s3.eu-west-3.amazonaws.com`), **not** the `s3-website` endpoint — OAC only works with the REST endpoint.
- **Origin access**: choose **Origin access control settings (recommended)** and create a new OAC (signing behavior: sign requests).
- **Viewer protocol policy**: Redirect HTTP to HTTPS
- **Cache policy**: `CachingOptimized`
- **Alternate domain names (CNAMEs)**: `example.com` and `www.example.com`
- **Custom SSL certificate**: the ACM certificate from step 2
- **Supported HTTP versions**: HTTP/2 and HTTP/3
- **IPv6**: on
- **Default root object**: `index.html`
- **Price class**: "North America and Europe" is enough for most sites and slightly cheaper
- **WAF**: optional — for a small static site you can skip it

### Allow CloudFront to read the bucket

After creating the distribution, CloudFront shows the bucket policy to apply (recent console versions can apply it for you). Otherwise, in S3 → your bucket → **Permissions** → **Bucket policy**, paste:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCloudFrontServicePrincipalReadOnly",
      "Effect": "Allow",
      "Principal": {
        "Service": "cloudfront.amazonaws.com"
      },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-static-website-bucket/*",
      "Condition": {
        "StringEquals": {
          "AWS:SourceArn": "arn:aws:cloudfront::YOUR_ACCOUNT_ID:distribution/DISTRIBUTION_ID"
        }
      }
    }
  ]
}
```

Replace `YOUR_ACCOUNT_ID` and `DISTRIBUTION_ID`. Only your distribution can now read objects; the bucket itself stays fully private.

## 4. Serve `index.html` in sub-folders

The default root object only applies to `/`. Because we use the REST endpoint, a request to `/about/` will **not** return `/about/index.html` on its own. Fix it with a tiny **CloudFront Function** (Functions → Create function, runtime `cloudfront-js-2.0`):

```js
function handler(event) {
  var request = event.request;
  var uri = request.uri;

  if (uri.endsWith('/')) {
    request.uri += 'index.html';
  } else if (!uri.includes('.')) {
    request.uri += '/index.html';
  }

  return request;
}
```

Publish it, then associate it with your distribution's default behavior on **Viewer request**.

## 5. Return real 404s

Many tutorials map every error to `/index.html` with a `200` status. For a regular static site this is a bad idea: every broken URL becomes a "soft 404" that search engines index as a duplicate of your homepage.

Instead, build a `404.html` page and, in **Error pages** → **Create custom error response**:

- **HTTP error code**: `403` → **Response page path**: `/404.html` → **HTTP response code**: `404`
- Repeat for **HTTP error code**: `404`

Why `403` too? Without `s3:ListBucket` permission, S3 answers `403 Access Denied` for missing files rather than `404`.

> Single-page app with client-side routing? Then map `403`/`404` to `/index.html` with a `200` — and accept the SEO trade-off.

## 6. Point your domain with Route 53

In your Route 53 hosted zone, create **alias** records (not CNAMEs) pointing to the distribution:

- **Record name**: empty (apex `example.com`) → type **A** → **Alias** → **Alias to CloudFront distribution** → select your distribution
- Same again with type **AAAA** (IPv6)
- Repeat both for **Record name** `www`

Alias records work at the apex (a CNAME cannot) and queries to them are free. Check propagation with [whatsmydns.net](https://www.whatsmydns.net/), then open `https://example.com`.

Serving both `example.com` and `www.example.com` works, but pick one as canonical: set a `<link rel="canonical">` on your pages, or add a host check to the CloudFront Function above that returns a `301` to your preferred domain.

## 7. Deploy (and redeploy)

Build, sync, invalidate:

```bash
npm run build
aws s3 sync ./dist s3://my-static-website-bucket --delete
aws cloudfront create-invalidation --distribution-id DISTRIBUTION_ID --paths "/*"
```

`--delete` removes files that no longer exist locally, and the invalidation clears the CloudFront cache so visitors see the new version immediately. The first 1,000 invalidation paths per month are free, and `/*` counts as one path.

A few refinements once it works:

- **Cache headers**: fingerprinted assets (`/_astro/`, `/assets/`…) can be uploaded with `--cache-control "public, max-age=31536000, immutable"`, and HTML with a short or `no-cache` policy. Then you only need to invalidate HTML.
- **CI**: run the same three commands from GitHub Actions, authenticating with an IAM role via OIDC rather than long-lived access keys. Give the role only `s3:PutObject`, `s3:DeleteObject`, `s3:ListBucket` on this bucket and `cloudfront:CreateInvalidation` on this distribution.
- **Quick checks and fixes**: to see what actually landed in the bucket, check a file's size or type, or swap a single image without a full rebuild, [Universal S3 Client](/gui/aws-s3) lets you browse and upload to the bucket from your iPhone, iPad or Mac. Remember to invalidate the path afterwards.

## What does it cost?

For a typical small site:

- **S3**: a few cents for storage and requests (CloudFront caches most reads)
- **CloudFront**: the always-free tier covers 1 TB of data transfer and 10 million requests per month; AWS also offers flat-rate CloudFront plans, including a free one
- **ACM**: public certificates used with CloudFront are free
- **Route 53**: $0.50 per hosted zone per month, plus the domain itself

## Conclusion

A private S3 bucket, CloudFront with OAC, an ACM certificate and two Route 53 alias records: that is a production-grade static hosting setup with HTTPS, a global CDN and no server to maintain. Once it's live, keep the bucket tidy with our [S3 best practices](/blog/s3-best-practices).
